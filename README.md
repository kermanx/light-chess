# 光镜棋（light-chess）

纸上的激光反射对决：Vue 3 + TypeScript + Vite，棋盘用 SVG 手绘风格渲染。
联机默认通过公共 MQTT broker 的 WebSocket 中继传输棋局消息，不依赖 WebRTC/UDP 穿透，
适用于使用代理或无法 P2P 直连的网络。**无需自建服务器**，构建产物是纯静态站点，可部署到 GitHub Pages。
保留 [trystero](https://github.com/dmotz/trystero) 的 Nostr/MQTT P2P 模式用于旧房间。

## 玩法

- 开局可勾选「生成预设基地与镜子」，用滑条指定每方额外镜子数（不含基地的 3 面镜子）。基地与双方/多方镜子一起随机生成，各方数量相同；逐步校验禁围及所有玩家的激光，保证开局无基地被命中，再枚举各方首手攻击，逐一检查是否存在合法单步防守；出现一手无解的攻击就整盘重生成。通过后直接开始，蓝方先手。这是排除一手必杀的战术检查，不保证长期胜率相同。支持当前棋盘尺寸、2～4 人、人类/AI 混合与联机；联机由房主生成一次并同步完整局面。刷新保留布局，重新开始按原数量重生成，预设镜子不进入撤回历史。
- 未开启预设开局时，每位玩家选一个格子作为家并指定开口，家中其余 3 条边自动放镜。家向四个方向发光，家镜同样对己方光线半反射（穿过 + 反射）。
- 基地可以同排或同列。布置按「位置 + 开口方向」检查，只禁止先手在开局立即命中基地的情况；后手的光路威胁不提前结算，先手仍有机会放镜自救。非法方向显示红色并拒绝确认。
- 之后按座位顺序轮流放镜子（每回合一个，不可移除）：点击网格边放边镜，左键格子放「/」斜镜，右键放「\」斜镜。对方基地的开口也可放镜，仍须遵守禁围规则。
- 己方镜子对己方激光是半反射（既穿过又反射），其他颜色的镜子必须反射。
- 「边界反射」默认开启：边界对所有颜色的光全反射；关闭时出界光线终止。开局前可设置，联机由房主控制并同步，进入对局后固定。该开关不影响禁围规则，边框始终算墙。
- 命中不立即生效：在每位玩家回合开头结算其激光，被击中的玩家出局（家变为 ✕）；双人局被击中即判负，多人局只剩一人时获胜。
- 每种颜色的边镜、斜镜分别连同边框，不能把任意两名存活玩家的家隔开（非法放置会被拒绝）；所有基地仍在同一区域时允许。
- 棋钟默认关闭；开启后默认每人 2 分钟，每次合法落子加 10 秒，只在自己的回合倒计时；所有基地布置完成后开始。开局前可调整或关闭，联机由房主设置及判定超时；超时出局，双人局对方获胜，多人局继续轮转。断线等待期间暂停，重连后恢复。
- 支持 2~4 人，单机同屏或联机（创建/加入 4 位房间号）。首页提供单机对战、创建房间和加入房间；在准备页选择人数、每个座位的人类 / AI 控制方式和规则。
- 创建房间默认勾选「公开」：公开房间会广播到 WebSocket 公共大厅，其他玩家在加入页可直接看到并点击进入。
- 新房号以 `3` 开头，棋局消息经 AES-GCM 加密后在多个 broker 上转发，并按对端编号、确认、重传、去重和排序。房号以 `1`/`2` 开头的旧房间仍走 Nostr/MQTT P2P；切换连接方式后需要重新分享链接。四位房号方便加入，不是私密口令。
- 房主可选「允许撤回一步」（默认不允许；单机始终可撤）。开启后每个人都能撤回自己刚下的那手，但开启该设置之前下的步骤不可撤；重新开始仅限房主。
- 开局后地址栏变为 `/s/<会话 id>`：刷新、浏览器后退（回大厅）+ 前进都能恢复对局。

## AI 对战

- 首页统一通过「单机对战」进入本地对局，可自由组合 2～4 个座位：同屏真人对战、挑战 AI 或全部交给 AI。
- 联机房间的所有座位（包括房主蓝方）都可设置为 AI，支持 Rust / WASM 和 DSH。AI 自动就座，只等待真人连接；计算与落子统一由房主负责，其他客户端接收权威结果。蓝方交给 AI 后，建房者仍保留房间管理权限，需保持房主页面在线；全部座位为 AI 时直接开局。
- 默认 AI 使用 Rust 编译成 WebAssembly，在独立 Worker 中运行。每步默认最多思考 10 秒，可选 3 秒或 30 秒上限；确定落子后可提前结束，棋钟剩余时间不足时自动缩短预算。
- 有 AI 时必须开启边界反射。真人先布置基地，AI 随后依次选择基地。所有 AI 动作都经过现有落子和禁围校验。
- 重新开始、掉线、回大厅、快照恢复会取消旧搜索。撤回后 AI 暂停，可继续撤回或点击「恢复 AI 思考」；轮到 AI 时棋钟一起暂停，真人回合仍照常计时。人类继续落子也会解除暂停，联机恢复由房主统一同步。
- AI 落子后显示该步的简短解释和实际思考耗时，并同步给联机玩家。说明与上一步落子绑定：下一手后隐藏，撤回时恢复相应记录，重开清空；旧引擎未提供解释时仅显示耗时。
- 引擎加载或搜索失败会显示错误和「重试 AI」，不会改用随机落子。刷新保存 AI 座位与思考上限。

引擎的数据结构、搜索算法与限制见 [ai/README.md](ai/README.md)。

AI 席位也可以选择 DSH：使用原生 `light-chess` preset，核心和棋局工具在浏览器 Worker 中运行，浏览器直接调用配置的 DeepSeek API。通过「管理 LLM 配置」弹窗保存多份模型配置，每个 DSH 席位独立选择，可让两个不同 LLM 自动对弈。测试页支持随时切换两种实现，并保存工具调用、落子解释与错误。对弈页右侧自动打开 DSH 轨迹面板，使用 `@deepseek-ai/trajectory-ui` 实时显示请求、模型输出、工具参数与结果；支持收起、查看每步历史和导出，轨迹保存在此浏览器，刷新后可恢复。DSH 需要单独打包现有 Harness 源码并配置 API Key，构建与接口说明见 [浏览器 DSH](scripts/dsh-browser/README.md)。

### AI 测试页面与记录

访问 `/ai-test`（本地预览为 `http://127.0.0.1:4173/ai-test`）即可下棋：固定 16×16、无棋钟、边界反射，蓝方人类先手、红方 AI，双方基地自动摆好。刷新继续当前对局；「新对局」创建独立记录，旧记录不会被覆盖。普通对局的存档不受测试模式影响。

每局有独立的 `/ai-test/<UUID>` 地址。所有合法落子、落子前后完整局面、撤回、思考上限修改、AI 原始请求/响应（含完整搜索统计）、取消/失败、刷新/离开都写入浏览器 IndexedDB。请求与实际落子通过 `searchId` 关联；`parentId` 与 `sequence` 保留事件顺序和分支。开局和刷新还记录引擎 SHA-256、规则代码摘要及构建时间，便于区别测试版本。步数统计包含后来撤回的落子。

`npm run dev` 和 `npm run preview` 同时提供本地记录服务，自动追加到 `debug/ai-games/<UUID>.jsonl`（一行一个事件，已加入 gitignore）。只有收到服务端写入确认，页面才显示「记录已保存到本地文件」。失败的上传在浏览器保留并重试，重复请求按事件 ID 去重；停止服务或更新构建不会删除旧记录。可用 `LIGHT_CHESS_AI_LOG_DIR` 环境变量指定其他目录。

静态部署没有本地写文件服务，仍会保留浏览器记录，并显示「仅保存在浏览器」。可点「导出当前记录」下载含完整事件的 JSON。清除网站数据会删除浏览器记录，但不会删除已经写入的本地文件。

### AI 对局回放

大厅和 AI 测试面板提供「对局回放」入口，地址为 `/replays`；每局独立地址为 `/replay/<UUID>`。打开从初始局面开始，用「上一步 / 下一步」、方向键、进度条或落子列表逐手查看，显示该步的真实光路、落子说明及搜索耗时。回放只读，不运行 AI，也不覆盖正在玩的存档。

本地 dev / preview 自动发现 `debug/dsh-games/` 中的 DSH vs 规则 AI 对局。完赛后运行 `npm run arena -- --publish --game <对局目录>`，将验证过的精简记录写入可提交的 `public/replays/`，随后构建即可在纯静态网站回放。DSH 对弈工具、记录格式及导出流程见 [对弈与回放](scripts/arena/README.md)。

## 本地开发

```bash
# 先安装 Rust；仓库工具链会自动安装 wasm32-unknown-unknown
npm install
npm run dev      # vite 开发服务器 :5173
```

默认使用公共 MQTT WebSocket 中继（EMQX 与 HiveMQ）。「中继已连接」只统计近期成功完成
消息往返的 broker。公共服务仍可能限流或不可用；可启动本地中继来进行独立回归：

```bash
npm run relay    # MQTT WebSocket 中继 :8788（仅供开发/测试）
```

然后在浏览器控制台执行一次（或在页面加载前写入 localStorage）：

```js
localStorage.setItem('light-chess:mqtt-relays', 'ws://localhost:8788')
```

清除该 key 即恢复默认公共中继；支持逗号分隔多个 MQTT WebSocket 地址。
旧 Nostr P2P 模式的测试中继仍可用 `npm run relay:nostr`（`:8787`）启动，覆盖 key 为 `light-chess:relays`。

## 校验脚本

```bash
npm run test:ai                  # Rust/WASM、规则差分、战术与控制器测试
npm run test:ai-page             # 构建 + 测试页、导出一致性及持久化端到端测试
npm run test:replay              # 历史光路、完赛导出、静态子路径及回放 UI
npx tsx scripts/sim-check.ts      # 光路模拟单元场景
npx tsx scripts/boundary-check.ts # 边界反射、规则锁定与存档兼容
npm run test:opening             # 预设开局的合法性、数量、存档、撤回及联机状态
npx tsx scripts/setup-check.ts    # 基地位置与开口方向、开局命中及多人布置
npx tsx scripts/clock-check.ts    # 棋钟加秒、超时、撤回、恢复、多人及客户端时差
npx tsx scripts/store-check.ts    # 规则/回合/围死判定（纯逻辑）
npx tsx scripts/ai-integration-check.ts # AI 序列化、权限、Worker 生命周期与过期结果
npx tsx scripts/ai-clock-check.ts # 撤回后 AI/真人棋钟、恢复广播和联机权限
npx tsx scripts/ai-analysis-check.ts # AI 落子说明、耗时、撤回/重开与旧存档兼容
node scripts/ai-mode-check.mjs    # 混合 AI 座位、房主调度、联机同步及重连（自带服务）
node scripts/ai-wasm-browser-check.mjs # 真实 WASM Worker、自动布置/落子、取消与混合联机（先 build:ai）
node scripts/ai-test-page-check.mjs # 测试直达页、真实 WASM、落盘/断网补传、撤回与刷新（先 build）
node scripts/visual-check.mjs     # 单机 UI 冒烟（需 dev 服务器）
node scripts/victory-check.mjs    # 棋盘致胜光路、命中时序、手机与减少动态效果（自带服务）
node scripts/enclosure-check.mjs  # 规则开关、边镜/斜镜禁围预览与落子（自带服务）
node scripts/mp-check.mjs         # 三人联机端到端（需 dev 服务器 + 本地中继）
node scripts/persist-check.mjs    # 刷新恢复（需 dev 服务器 + 本地中继）
node scripts/relay-check.mjs      # 禁用 WebRTC；丢包/乱序/重复/中继故障回归（自带服务）
```

## 部署

`npm run build` 产出 `dist/`（`base: './'`，可挂任意子路径）。
仓库自带 `.github/workflows/deploy.yml`：push 到 `main` 即自动构建并发布到 GitHub Pages。

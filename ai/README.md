# Rust / WASM 搜索引擎

引擎使用确定性的光路计算和博弈搜索，无神经网络、训练数据或网络推理。只处理边界反射开启的局面。双人策略为主要目标；多人按真实轮转和淘汰规则运行，以所有其他玩家都倾向于击败本方的保守模型评价。

## 运行和接口

项目根目录的 `rust-toolchain.toml` 固定 Rust 版本和 `wasm32-unknown-unknown` 目标。`npm run build:ai` 编译并复制产物到 `src/ai/engine.wasm`；`npm run dev`、`npm run build` 会自动先构建引擎。WASM 产物和 Cargo target 不入库。

浏览器通过独立 Worker 调用 WASM。每次搜索传入一次 v1 JSON 快照，返回一个动作和统计。搜索不访问 Vue/store，不持有 JS 对象。最终动作仍由 TypeScript 棋局权威层检查和结算。

本地预览运行期间重新构建会保留 `dist` 中旧版哈希资源，确保已经打开的页面在后续回合仍能加载配套的 Worker / WASM。页面刷新后才切换到新版；需要清理旧产物时，应先停止预览并结束旧页面。CI 的干净构建不受影响。`node scripts/ai-preview-update-check.mjs` 验证页面打开后重新构建，旧页面仍能完成真实 AI 落子。

原生 ABI：

- `alloc(length) -> pointer`：分配输入缓冲区。
- `choose_action(pointer, length) -> resultPointer`：读取 UTF-8 JSON 并运行搜索。
- `result_len() -> length`：输出 UTF-8 JSON 的字节数。
- `dealloc(pointer, length)`：分别释放输入、输出。缓冲区使用 `Box<[u8]>`，无需推断 Vec capacity。
- 导入 `env.now_ms() -> f64`：Worker 提供 `performance.now()`。

输入字段与 TS 类型定义见 `src/ai/protocol.ts`。坐标和颜色编码如下：

- `horizontal[y * N + x]`：水平边，长度 `N*(N+1)`。
- `vertical[y * (N+1) + x]`：垂直边，长度 `(N+1)*N`。
- 边值 `0` 为空，`1..4` 为颜色编号 `0..3` 加一。
- `diagonals[y * N + x]`：格内斜镜，长度 `N*N`，`0` 为空，非空值为 `1 + 2*颜色 + 朝向`，朝向 `0=/`、`1=\`。
- `homes[4]` 保存基地，`players` 保存座位轮转顺序，`aliveMask` 保存存活玩家。

引擎没有 16、36、48 等棋盘常量。数组按输入 N 分配并校验长度/索引范围；实际可运行尺寸受机器内存和预算约束。游戏 UI 原有 16～48 限制独立于引擎。

## 数据结构

`board.rs` 使用三个 `Vec<u8>` 保存镜子。`home_at` 为每格缓存基地颜色。光线状态编码为 `4*(y*N+x)+入射方向`；方向依次右、下、左、上。

`optics.rs` 用队列遍历最多 `4N²` 个光线状态。每格一个方向位图消除反射环路；防守分析额外记录父状态和实际穿过/反射的边，普通评估不分配路径数组。出局基地仍吸收光，禁围检查只考虑存活基地，与原规则一致。

禁围使用每格四个三角区域的洪泛。落子仅修改一个字节，并以确定性散列增量更新局面键；递归返回或中断时撤销镜子，同时恢复当前玩家和存活掩码。局面缓存键包含镜子布局、基地、尺寸、当前玩家和存活状态。

## 决策顺序

1. **先检查即时安全。** 每个候选实际试放，完整计算禁围和激光反射。下一位玩家开头的光束会击中本方时，该手不能作为安全候选。被攻击时，穷尽一条命中路径上的防守位置，再用完整光路检查新反射和其他攻击分支。根节点对全部合法防守计算挡住后的双方连接代价，并检查落子后对手的连续强攻，再保留不同区域、镜子类型的代表；内部节点按实际光路变化预选斜镜、横镜、竖镜和反击。不能沿用进攻排序而漏掉纯防守的截断，也不能让同一列的相似挡法占满根候选。找到多种安全手后只展开一部分；若要声称没有防守或只有一手，则必须穷尽候选。唯一救命手直接落子。
2. **重建进攻方案。** 己方前向光路与目标基地在己方规则下的反向图连接。反向图使用字典序最短路：先最少新增镜子，再以光路长度打破同分。保存后继，恢复最多六面镜子的实际方案；依次试放，检查每步禁围、朝向冲突和最终是否命中。只将通过验证的方案用于根节点优先排序。该验证假设对手尚未插手，不构成必胜证明。
3. **在截断候选之前找直接胜负。** 所有可能一手接通的攻击都检查是否存在合法挡法。只要存在一种挡法，就不能叫必胜；遍历完整命中路径候选且没有挡法，才能返回 `forced-win`。叶节点也检查当前玩家的一手不可防攻击，避免普通深度边界漏掉致命应对。根节点若发现对手下一步能制造这种攻击，额外生成占位、截断和提前防守候选。
4. **保留不同路线，比较斜镜方向。** 普通根节点保留约 12 个落点，发现对手不可防的准备后扩大到约 32 个，内部战略节点约 8 个候选。按相对目标的位置保留不同方向的方案，避免相邻空行占满列表。根节点为每个选中落点保留两个合法、安全的斜镜方向，因此最多约 24 / 64 个动作；同一落点不重复占用区域配额。本方光路相同不表示敌方后续反射相同，不能在根节点仅凭静态分合并朝向。内部战略节点仍使用光路签名作启发式压缩；签名和区域分组都不用于胜负证明。横纵镜仍保留作救命、截断和更强的战术用途。
5. **搜索真实应对。** 双人 Alpha-Beta，多人用本方最大化、其余玩家最小化的保守模型。顺序严格是“放镜 → 下一位玩家 → 结算其光束 → 再行动”。根节点使用完整评分窗口比较候选，避免把剪枝边界当成精确同分；固定候选宽度允许置换表跨深度复用。深度边界的攻击展开防守；防守若带反击，会继续处理，最多额外延伸三层。同一局面的防守排序按候选宽度缓存，避免每轮加深都重复计算。
6. **无需防守时优先直接进攻。** 双人根节点将已验证安全、能立即命中的落法放在普通发展手之前。对方下一手能挡住，不会取消这项优先级；它花一手应对本身就有价值。继续搜索对方的防守和反击，在直接攻击之间比较后续；搜索发现败势的攻击不优先于未发现败势的其他落法，搜索发现的获胜变化也优先。战略搜索仍有候选剪枝，这些深层胜负值不是全树证明。完整迭代、被中断迭代的同层比较以及搜索尚未完成时的安全回退都执行同一进攻优先规则。
7. **按搜索稳定程度结束。** 只有一手能守住、证明不可防攻击时立即返回。其他局面至少完成四层，同一候选连续三个完整深度保持第一、所有根候选在相邻深度的估值波动均不超过阈值，才允许提前结束。只看第一名会漏掉仍在大幅变化的其他方案。候选分数接近只能说明暂时分不清，不能作为停止理由。还会根据上一轮耗时估计下一轮能否完成。时间是上限；中断时可保留同一更深层已经算完的新旧候选比较，否则回到上一轮完整结果或已验证安全的候选。

## 连续强攻证明

`forcing.rs` 在双人根节点增加独立的 AND/OR 搜索。进攻方尝试能实际命中的落子；防守方从一条真实命中光路上生成可能挡法，逐一检查禁围并重算完整光路。任何合法防守都必须有已证明的后续攻击，包括能够反击的挡法。直到某次攻击确实没有合法挡法，才形成一份包含所有防守分支的证书。

默认最多证明四次连续进攻，按攻击次数逐层加深；分配剩余思考时间的 20%（最多 4 秒）和剩余节点预算的四分之一（最多 20,000 次检查）。没有找到证明时继续普通搜索，不把未知当成失败或胜利。进攻候选来自连接图，可能漏掉其他赢法，因此这里只作正向证明。防守分支不按宽度裁剪，预算中断也不能把尚未检查的挡法当成失败。所有临时镜子在正常返回、中断和成功时都会撤销。

另外，根节点会在实际试放并结算下一回合后，将对手设为进攻方，检查最多四次连续强攻。防守模式覆盖全部合法挡法，再进行候选宽度裁剪；安静局面检查已选出的战略候选。此检查独立于普通 Alpha-Beta 深度，普通深度只有一层时也能发现三次强攻。分配剩余时间的 30%（最多 4 秒）和剩余节点的三分之一（最多 40,000 次检查），按候选均分并将未用完的预算留给后续候选。只有完整证书才能将该候选标记为已证明会输；`unknown` 和 `budget` 均不能说明安全。证实的败势优先级低于未被证实的候选，也不会因迭代中断而重新成为回退选择。

找到连续强攻后，`stopReason` 为 `forcing-win`，普通搜索 `depth` 仍为 0。`forcing.proof` 递归保存进攻动作、全部合法防守及各自后续；`winningTurns` 是最坏应对下还需要的进攻落子次数，不含防守方落子和最终回合开头结算。普通 Alpha-Beta 的大分值与这类完整防守证明分开记录。

若已经穷尽当前威胁的防守且无一可用，返回 `no-defense`，选择仍合法的落子，让游戏正常结算失利。此时 `safe` 为 false。已证明无法防守不再被误报为引擎加载或搜索错误；如果棋盘连任何合法落子都没有，仍不伪造动作。

## 评估、数据和边界

`planning.rs` 保存具体新增镜子序列、剩余光路长度、后续落点被敌方光路覆盖的数量。规划时双方棋子位置固定，因此“还需两面镜子接通”表示存在合法的静态连接方案，不表示两回合内必胜。

节点评估使用快速反向 0-1 BFS 的连接代价、直接连接机会和实际防守数量。不再给经过更多空格的光束加叶节点评分：这种几何长度不等于有效进攻。覆盖量只用于防守候选的粗略排序。双人安静局面加入半步的先手修正，避免“各差几面镜子”的比较忽略下一手归属，造成奇偶深度的机械波动；这仍是启发式估值。构造具体方案时另用带后继的字典序 Dijkstra，避免每个叶节点都承担路径恢复成本。已形成的攻击按实际挡法数量区分压力，不能用重叠光路条数冒充独立攻击路线。防守计数可以提前停止：例如已找到四手，只能说明至少四手，不能拿来证明唯一挡法或必胜。

最终根节点按层级比较：先避开有完整对手强攻证书的败着，再处理普通搜索发现的胜负；无需防守时直接攻击优先于普通发展。同类候选比较搜索分数，斜镜仅加 20 分作为接近分数时的偏好，不能压过明显更好的横竖镜；大幅胜负值不加镜子类型分。原始估值、排序分、选择分和优先级分别记录。

战略节点仍然有候选剪枝；反向距离仍然是松弛估计；自动提前结束也不是数学收敛证明。`forced-win` 只用于根节点完整验证的双人即时战术；`forcing-win` 要有完整覆盖防守的连续进攻证书。普通大分值不表示完整博弈树必胜。多人继续遵守真实轮转，不将所有玩家光束同时结算，也不套用双人的不可防证明。

- `depth`：完成的常规搜索深度；`0` 也可能是直接证明唯一防守或不可防攻击。
- `selectionDepth`：实际选手比较的深度。下一层中断时，先完整算完旧选择，再与同层已算完的新候选比较，允许保留改进；不使用深浅不同的分数来换手。此时可能比 `depth` 大一，未搜索完的其他候选仍可能更好。
- `nodes`：博弈搜索节点数加双方连续强攻的落子检查次数（后者另记在 `forcing.nodes` 和 `counterplay[].nodes`），不含普通候选生成和防守计数里的每次光路计算。
- `safe`：不会被下一位玩家开头结算的光束立即淘汰，不保证远期安全。
- `defenseComplete`：当前直接威胁的合法防守是否全部保留，没有因搜索宽度截断。
- `candidates` / `plans`：根节点搜索候选数 / 通过实际试放的连接方案数。
- `stopReason`：唯一防守、无解防守、直接胜利、连续强攻证明、候选稳定、深度、时间或节点上限。
- `reason`：这一步的简短说明。前端将说明和实际耗时绑定到权威落子，支持联机、撤回与存档恢复。
- `score`：搜索估值，不是胜率。
- `forcing`：连续强攻检查的次数、耗时、尝试/完成的攻击深度及状态。`proven` 附完整证明；`unknown` 表示此范围内未证明；`budget` 表示中断。后二者均不表示没有赢法。
- `counterplay`：各根候选落子后，对手强攻检查的状态、耗时、节点与完整证书。防守时在裁剪前记录，可能包含未进入普通搜索的挡法。`proven` 表示该落子会输给这条连续强攻；未证明不代表长期不会输。
- `iterations`：每一层完整搜索的全部根候选、原始 `score`、含斜镜偏好的最终 `selectionScore`、启发式排序分和 `line` 应手序列。序列从该候选开始，后续来自缓存的搜索选择，可能是剪枝后的不完整变化，不代表所有应对或必胜证明。测试页将其存入原始搜索结果，便于对照不同方案和深度。
- 候选的 `directAttack` 记录该手试放后是否实际命中；`selectionPriority` 记录决策层级（0：对手强攻已证明会输，1：普通搜索发现败势，2：普通发展或防守，4：无需防守时的直接攻击，5：搜索发现获胜变化）。先比较层级，再比较含斜镜偏好的 `selectionScore`，保留原始 `score`，避免把进攻偏好伪装成更高静态估值。
- `partialIteration`：中断层里已经完成的候选比较，与完整层分开记录。

预算在候选、战术证明和搜索节点之间检查。一次光路或禁围遍历会完成并撤销后再返回，因此巨型棋盘可能略超预算。Worker 仍支持取消与超时保护。

## 验证

`npm run test:ai` 包括 Rust 路线重建与撤销测试、真实 WASM ABI、160 个局面的 TypeScript 规则差分、任意尺寸及 2～4 人对弈、战术回归、控制器和落子说明生命周期。`ai/fixtures/` 包含用户截图复原、16×16 测试页的真实第一手、唯一救命边镜、不可防攻击、尚未命中但已有致命后续的局面。战术结果由独立的原 TypeScript 模拟器枚举合法应对验证。连续强攻证书另用 TypeScript 枚举全棋盘落子，逐层核对每个合法防守是否都被覆盖；包括两次/三次进攻、多种挡法，以及已无法防守时正常结算的回归。Rust 单测逐个节点预算打断证明，检查不会误报胜利或残留试放镜子。`counter-forcing.json` 复现实际对局蓝方第六手：独立枚举 16 种合法挡法，在普通搜索仅一层时也须避开已证实的三次强攻败着，并逐层复核所有对手证书；中断检查不得误报安全或败势。

可将测试记录中的 `search-start.detail.detail.request` 提取为单行 JSON，通过 `cargo run --release --manifest-path ai/Cargo.toml --bin engine < request.jsonl` 在原生引擎重放。可选 `minDepth` 只提高自适应停止的最低深度，不绕过时间/节点上限；`maxDepth` 限制最大深度。原生与 WASM 共用算法，墙钟预算下完成的深度可能不同。

`node scripts/ai-mode-check.mjs` 检查混合座位、联机、刷新恢复和错误处理；`node scripts/ai-wasm-browser-check.mjs` 使用真实 WASM 检查自动落子、两真人一 AI 联机，以及思考期间撤回/重开取消。脚本自带本地服务，不会连接公共房间。
